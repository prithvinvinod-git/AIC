# servox-phi (servox / AIC) — App Brief

Living compaction of the app. The code is the source of truth; this file is the map.
> Note: `CONTEXT.md` / `docs/app_status.md` describe an older validator-only model (no heads, 11 statuses). The code now has **14 statuses and 9 roles incl. two heads** — this brief reflects the code and supersedes them.

## 1. What it is
Closed-loop campus maintenance ticketing with AI assistance. Reporter raises → dept **validator** screens (sets priority) → HOD/Principal approve P1–2 criticals → **maintenance head** routes the job → **category head** assigns a team → worker executes → category head inspects on-site → reporter rates → closed. Every mutation is audited on a timeline; SLAs enforced per priority; in-app + (optional Gmail-SMTP) email notifications.
**Core rule: "AI suggests, the state machine decides."** Every status change goes through the machine and requires a human.

- Live: https://servox-phi.vercel.app · Firebase project `campus-maintenance-2820d` (real cloud, no emulator).

## 3. Roles (9) — `src/lib/types.ts`
`reporter · validator · hod · principal · maintenance_head · category_head · maintenance · purchase · admin`
- **validator** (department-scoped): screens NEW, routes/assigns, blocks jobs, complets. Verifies nothing — completion verification moved to category head.
- **hod / principal**: ESCALATED→APPROVED/REJECTED (optional severity revision). `purchase` not in the machine — approves/rejects flagged requirements with unit price (auto-resolves) or reason.
- **maintenance_head / category_head**: dispatch chain (see below), with category heads scoped to `routing.categoryHeadUid`.
- **admin**: override on nearly all transitions; `portal` claim lets a single admin navigate as principal/hod/admin (e.g. `admin@gmail.com`).

## 4. Statuses & transition table (14) — `TRANSITION_RULES` in `src/lib/issueMachine.ts`
```
NEW → VALIDATED → ESCALATED → APPROVED → ROUTED → PENDING_ASSIGN → ASSIGNED → ONGOING
  └→ REJECTED (terminal)                               │         │
                                                       └→ ASSIGNED →┘
ONGOING → COMPLETED → INSPECTED ──auto──→ VERIFIED → CLOSED (terminal)
   └→ PENDING (blocker) → PENDING_ASSIGN | ASSIGNED
COMPLETED ──send-back──→ ONGOING (category head)
```
| From | To | Roles | Precondition |
|---|---|---|---|
| NEW | VALIDATED | validator, admin | priority 1–5 |
| NEW | REJECTED | validator, admin | reason ≥3 chars |
| NEW | ESCALATED | admin | `safetyEscalation` (AI hazard) |
| VALIDATED | ESCALATED | validator, admin | — (P1–2 **auto**: 2 tl entries) |
| VALIDATED | ROUTED | validator, admin | — (P3–5 **auto** to maintenance head) |
| VALIDATED / APPROVED | ASSIGNED | validator, admin | direct assign |
| ESCALATED | APPROVED / REJECTED | hod, principal, admin | approve: severity 1–5 optional; reject: reason |
| APPROVED | ROUTED | validator, admin | — |
| ROUTED | PENDING_ASSIGN | maintenance_head, validator, admin | categoryId |
| ROUTED | ASSIGNED | admin | — |
| PENDING_ASSIGN | ASSIGNED | category_head, maintenance_head, admin | teamId + workers |
| ASSIGNED | ONGOING | maintenance | must be assigned staff/team |
| ASSIGNED / ONGOING | PENDING | maintenance, validator, admin | blocker note ≥3 |
| ASSIGNED / PENDING | PENDING_ASSIGN | category_head, maintenance_head, validator, admin | — |
| ONGOING | COMPLETED | maintenance, validator, admin | report ≥5; **all** `needsApproval` reqs resolved |
| COMPLETED | INSPECTED | category_head, admin | verdict ≥2 (auto→VERIFIED) |
| COMPLETED | ONGOING | category_head, admin | sendBackReason ≥3 |
| VERIFIED | CLOSED | reporter | rating 0.5–5 (half steps) or `isAuto` (auto-close) |
| REJECTED / CLOSED | terminal | — | — |

**Machine behaviors** (`applyTransition`, single Firestore transaction): P1–2 validate → auto-ESCALATED (escalation pending); P3–5 validate → auto-ROUTED (denormalizes `routing.maintenanceHeadUid`); INSPECTED → sets verification + auto-VERIFIED timeline; COMPLETED does **not** cascade (waits for category-head inspection). SLA (`initSla`): P1–2 at APPROVED, P3–5 at ASSIGNED; paused while PENDING (`pausedAt`/`totalPausedMs`), resumed/extended at ASSIGNED; `breachedFlags` drive queues. Every mutation = transaction + timeline entries.

## 5. Architecture invariants
- **All writes via Next Route Handlers** → `src/lib/transition.ts runTransition` (auth → Zod → `applyTransition` → notifications → `after()` email hooks); the generic `POST /api/issues/[id]/status` is the ONE door. Thin wrappers: `/validate /reject /escalate /approve /forward /assign /pending /complete /inspect /verify /sendback /feedback`.
- Role checks in handlers (Admin SDK ID token + custom claims); Firestore rules = defense-in-depth only. Denormalized display data; composite indexes; counters transactional; images = base64 blobs in `imageBlobs` served via `/api/images/[id]`.
- Crons (Vercel, `CRON_SECRET`): sla-reminders 09:00 UTC, auto-close 10:00, **escalate-stale 08:30** (forces P1–2 stuck in NEW >24h through VALIDATED→ESCALATED plus alerts). Cloud Functions: 10-min SLA breach scan, 60-min reminders, Mon weekly digest (in-app).

## 6. AI surfaces (7 Genkit flows, `src/lib/ai/`) — LLM-first, deterministic fallback, never touches `status`
F1 triage+photo (on create via `after()`), F2 duplicates (token-overlap, same location, threshold 0.45), F3 routing suggestion (rule engine + AI reason), F4a requirements extraction + pre-job **IssueBriefing** (probable cause / safety / tools / skill / ETA), F4b closure draft, F5 weekly insights, F6 root cause, F7 at-risk locations. Guarded by `aiSuggestion.aiProcessed`; write only into `aiSuggestion`. Gate: `GOOGLE_GENAI_API_KEY`/`GROQ_API_KEY` present (model chain Gemini 3 → Groq → legacy).

## 8. Security / ops hardening shipped (P0 audit)
Password-reset flow (`sendPasswordResetEmail`, no enumeration) · in-memory sliding-window rate limits (`/api/auth/provision`, `/api/track/[token]` 30/min, `/api/images/[id]` 120/min) · tracking-token revoke (admin/principal, audited) + auto-revoke 30d post-close (410) · upload gate (`imageGate`: magic-byte re-detect JPEG/PNG/WebP/HEIC + embedded-script scan + sha256 verified on serve) · stale-critical auto-escalation · smoke scripts refuse prod without `SMOKE_ALLOW_PROD=1` and tag `smoke:true` · error monitoring (`logError` → `logs/errors` + daily counter, wired into `handleError` + `after()` hooks; `GET /api/health`).
